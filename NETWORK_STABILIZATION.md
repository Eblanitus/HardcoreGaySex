# Стабилизация HardcoreMelee

## Этап 1 — Амарок (изменения внесены, игровая проверка требуется)

Выбрана стандартная для player-owned projectile модель: владелец рассчитывает
управление, переходы состояний, рост льда и создаёт дочерние снаряды.
Сервер и наблюдатели продолжают движение по полученной скорости, но не запускают
машину состояний на основе своего курсора или несинхронизированного ModPlayer.
Это не серверно-авторитетная защита от читов.

`SendExtraAI`/`ReceiveExtraAI` передают режим, количество льда, фактический размер
хитбокса и интервал ударов. Позиция и скорость идут в стандартном SyncProjectile.
Обновление запрашивается при смене режима, изменении льда, попадании и каждые
10 тиков. Поздно присоединившийся наблюдатель получает текущее состояние через
netImportant и ExtraAI. Цель наводки не нужна наблюдателям: решения принимает
только владелец, а не несколько независимых симуляций.

На сервере снаряд удаляется, если владелец умер или отключился. Обычное завершение
возврата выполняет владелец. Осколки и переход после попадания создаются только
владельцем. Кулдаун отрыва сосульки теперь отсчитывается в тиках, а не попаданиях.

### Что проверить в tModLoader

Нужны одиночная игра, host-and-play и отдельный dedicated server с двумя клиентами.

- [ ] Обычная ЛКМ: полёт, смена направления курсора, отпускание и возврат.
- [ ] ПКМ без ЛКМ: запуск и наводка; на сервере йо-йо не уходит домой сразу.
- [ ] Наводка без цели, смена четверти курсора, смерть/исчезновение цели.
- [ ] ЛКМ + ПКМ: круг, полный разгон, выход из круга и попадание в режиме круга.
- [ ] У наблюдателя движение не зависит от его собственного курсора.
- [ ] Стены: отскок/скольжение и рост хитбокса без проникновения в блоки.
- [ ] Лёд: рост, отрыв не чаще раза в 45 тиков, полный взрыв без дублей осколков.
- [ ] Перчатка и сумка: двойник, противовесы, снятие аксессуара.
- [ ] Смена оружия, смерть, выход владельца с сервера: снаряды не остаются навечно.
- [ ] Вход второго игрока во время полёта/круга и при полном льде.
- [ ] При задержке сети 100–200 мс оценить рывки при коррекции каждые 10 тиков.

Полноценное сглаживание сетевых коррекций не добавлено; наблюдатели экстраполируют
последнюю скорость. Визуальные эффекты владельца (например кольцо полного разгона)
пока не являются отдельными сетевыми событиями.

## Этап 2 — общая геометрия FrostMelee (изменения внесены)

`WeaponCollisionMasks.Generated.cs` содержит запечённые маски alpha > 128 для
IceSpearHeld, Ice_Blade, Frostbrand и IceSpearFrozen. Get/GetZone теперь строят
геометрию и сектора одним CPU-алгоритмом на сервере и клиенте, без Texture2D,
GetData и зависимости от загрузки графических ресурсов. Неизвестный тип по-прежнему
использует запасную геометрию; все три текущих типа оружия покрыты масками.
Ресурспаки и подмены текстур другими модами теперь не меняют боевую дальность.

Шкала Frost реплицируется через сервер (проверяются отправитель, размер пакета,
конечность и диапазон значения); пересечение порога замороженной зоны отправляется
сразу, остальные изменения — не чаще раза в 6 тиков. Входящий клиент получает
снимок ресурса. Это синхронизация owner-authoritative ресурса, а не серверная
проверка правомерности его накопления. При задержке сети порог виден не мгновенно.

Генератор и проверки:

```sh
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements.txt
.venv/bin/python tools/generate_collision_masks.py         # после изменения PNG
.venv/bin/python tools/generate_collision_masks.py --check # проверка актуальности
.venv/bin/python -m unittest discover -s tests -v
```

Четыре Python-теста проверяют порог прозрачности, порядок битов, каждый пиксель
масок, актуальность генерации и отсутствие GPU-зависимостей в построителе.
Это тесты данных/архитектуры, не тесты C#-коллизий. Нужна игровая проверка взмаха,
тычка, выставленного оружия и броска с обеими зонами на dedicated server.
ReaperMelee и WoodSwordsOverhaul на общие маски пока не переведены.

## Сборка и ограничения проверки

Путь к установленному tModLoader можно передать без редактирования файлов:

```sh
dotnet build FrostMelee/FrostMelee.csproj -p:TModLoaderPath="/path/to/tModLoader"
dotnet build ReaperMelee/ReaperMelee.csproj -p:TModLoaderPath="/path/to/tModLoader"
dotnet build WoodSwordsOverhaul/WoodSwordsOverhaul.csproj -p:TModLoaderPath="/path/to/tModLoader"
```

Также поддерживается переменная окружения `TModLoaderPath`; старый Windows-путь
сохранён как значение по умолчанию. Требуются SDK и зависимости установленного
tModLoader. Версию tModLoader для релиза ещё нужно зафиксировать после реальной
проверки сборки; добавлять CI без известных зависимостей пока преждевременно.

В текущем окружении нет dotnet и tModLoader, поэтому компиляция и игровые сценарии
не выполнялись. Выполнены проверка whitespace через git diff --check, разбор XML
файла targets, четыре Python-теста и проверка актуальности запечённых масок.

Добавлен .gitignore для новых артефактов. Уже отслеживаемые obj/резервные копии
не удалялись, чтобы не смешивать сетевые изменения с массовой чисткой истории.
