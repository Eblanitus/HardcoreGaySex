# Сводный вывод по ответам двух моделей (мигание копья)

## Модель 1

- **Причина:** Мёртвых кадров **два** (N+1 и N+2), а не один. На N+1 движок уже убивает снаряд при `itemAnimation == 0`; на N+2 создаётся новый.
- **Решение:** Продлевать жизнь на **2 кадра**: при `itemAnimation <= 0 && timeLeft <= 1` ставить `timeLeft = 3`. Прогресс при `itemAnimation <= 0` принудительно `0` (копьё убрано). Критичный момент — кадр, когда `itemAnimation` уже 0, а не 1.

## Модель 2

- **Идея:** Не управлять `timeLeft` вручную (это давало «удлинение» анимации), не вызывать `Kill()`. При `duration <= 0` не убивать снаряд, а переводить в «покой» (velocity = 0, позиция у руки), оставлять живым.
- **Риск:** Если старый снаряд не убивать, при следующем ударе будет два снаряда (старый + новый), если только движок сам не убивает старый при новом use. Без проверки кода движка подход неоднозначен.

## Общий вывод

1. **Два мёртвых кадра** — правдоподобно и совпадает с наблюдением: продление на 1 кадр дало лишний кадр с копьём, но пустой кадр остался.
2. **Реализуем решение Модели 1:** продление на 2 кадра (`timeLeft = 3` при `itemAnimation <= 0 && timeLeft <= 1`), при `itemAnimation <= 0` — `progress = 0`. Логика «не убивать, только пауза» (Модель 2) без подтверждения поведения движка не внедряем.
3. **Условие по `itemAnimation`:** Триггер — момент, когда `itemAnimation` уже 0 (кадр после окончания анимации), а не 1, как было в нашей прошлой попытке.

## Что вносим в код

- В PreAI после `player.heldProj = ...`: если `player.itemAnimation <= 0 && Projectile.timeLeft <= 1`, то `Projectile.timeLeft = 3`.
- После расчёта progress: если `player.itemAnimation <= 0`, то `progress = 0f`.
- Остальная логика (позиция, вращение, velocity) без изменений.
