# Анализ мода ReaperMelee на ошибки

## Критические ошибки

### 1. Отсутствующие текстуры (папка `Items`)

Мод ссылается на текстуры, которых **нет в проекте**:


| Где используется                                                                              | Путь к текстуре                                              |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| [GlobalItems/GlobalItem.cs](GlobalItems/GlobalItem.cs) (PreDrawInWorld, PreDrawInInventory)   | `ReaperMelee/Items/IceSpear`                  |
| [GlobalItems/GlobalItem.cs](GlobalItems/GlobalItem.cs)                                        | `ReaperMelee/Items/DeathSpear`                |
| [Projectiles/IceSpearProjectile.cs](Projectiles/IceSpearProjectile.cs) (свойство Texture)     | `ReaperMelee/Items/Длинное ледяное копье.png` |
| [Projectiles/DeathSpearProjectile.cs](Projectiles/DeathSpearProjectile.cs) (свойство Texture) | `ReaperMelee/Items/Длинное копье смерти`      |
| [Projectiles/IceSickleProjectile.cs](Projectiles/IceSickleProjectile.cs)                      | `ReaperMelee/Items/IceSpear`                  |
| [Projectiles/DeathSickleProjectile.cs](Projectiles/DeathSickleProjectile.cs)                  | `ReaperMelee/Items/DeathSpear`                |


В корне мода **нет папки `Items`** и **нет ни одного файла `.png`**. При загрузке мода или при отрисовке возможны исключения из-за отсутствующих ресурсов. Нужно либо добавить папку `Items` и все указанные текстуры, либо временно убрать/заглушить кастомную отрисовку и пути к текстурам.

Дополнительно: пути с **кириллицей** (`Длинное ледяное копье.png`, `Длинное копье смерти`) могут давать сбои на разных системах и кодировках; надёжнее использовать латиницу (например, `IceSpearLong`, `DeathSpearLong`).

## Потенциальные баги и несоответствия

### 2. Неиспользуемые классы проектий: IceSickleProjectile и DeathSickleProjectile

- Предметы по [GlobalItem.cs](GlobalItems/GlobalItem.cs) стреляют **копьями**: `ModContent.ProjectileType<Projectiles.IceSpearProjectile>()` и `ModContent.ProjectileType<Projectiles.DeathSpearProjectile>()`.
- При попадании копья в [IceSpearProjectile.cs](Projectiles/IceSpearProjectile.cs) и [DeathSpearProjectile.cs](Projectiles/DeathSpearProjectile.cs) в `OnHitNPC` создаётся **ванильный** снаряд: `ProjectileID.IceSickle` и `ProjectileID.DeathSickle`.

В результате модовые классы **IceSickleProjectile** и **DeathSickleProjectile** нигде не создаются и являются мёртвым кодом. Варианты:

- Если задумка — вылетающий при попадании **ванильный** серп: текущая логика верна, тогда классы `IceSickleProjectile` и `DeathSickleProjectile` можно удалить (или оставить только при планах их использовать позже).
- Если задумка — вылетающий **модовый** снаряд: в `OnHitNPC` нужно спавнить `ModContent.ProjectileType<IceSickleProjectile>()` / `ModContent.ProjectileType<DeathSickleProjectile>()` вместо `ProjectileID.IceSickle` / `ProjectileID.DeathSickle`.

### 3. Отрисовка копья (PreDraw): возможная инверсия flip

В [IceSpearProjectile.cs](Projectiles/IceSpearProjectile.cs) и [DeathSpearProjectile.cs](Projectiles/DeathSpearProjectile.cs) в `PreDraw`:

```csharp
float rotation = Projectile.spriteDirection >= 0 ? 0f : MathHelper.Pi;
SpriteEffects flip = SpriteEffects.FlipHorizontally;  // всегда FlipHorizontally
// ...
Main.spriteBatch.Draw(..., rotation, ..., flip, ...);
```

`flip` всегда `FlipHorizontally`, независимо от `spriteDirection`. Обычно при направлении влево используют flip, при направлении вправо — нет. Стоит проверить в игре: если копьё смотрит не в ту сторону, то задавать `flip` по направлению, например:

- `SpriteEffects flip = Projectile.spriteDirection >= 0 ? SpriteEffects.None : SpriteEffects.FlipHorizontally;`

(и при необходимости скорректировать `rotation`).

### 4. Несоответствие имён файла и класса

- Файл: [GlobalItems/GlobalItem.cs](GlobalItems/GlobalItem.cs).
- Класс: `GlobalSpears`.

Имя файла не отражает класс; для единообразия и поиска по коду лучше переименовать файл в `GlobalSpears.cs` (и при необходимости обновить ссылки в документации/проекте).

### 5. Разные версии в mod.json и build.txt

- [mod.json](mod.json): `"version":"1.0.0"`.
- [build.txt](build.txt): `version = 0.1`.

tModLoader обычно берёт версию из `build.txt`. Имеет смысл привести к одному формату и значению (например, везде `1.0.0` или `0.1`), чтобы версия в лаунчере и при сборке совпадала.

## Что сделано корректно

- **GlobalItem**: класс `GlobalSpears` наследует `GlobalItem` — в tModLoader такие классы подхватываются автоматически, отдельная регистрация в `Mod` не нужна.
- **Проверка индекса после NewProjectile**: условие `spawnedIndex >= 0 && spawnedIndex < Main.projectile.Length` перед обращением к `Main.projectile[spawnedIndex]` — корректно.
- **Сетевая синхронизация**: спавн дополнительного снаряда в `OnHitNPC` ограничен `if (Projectile.owner != Main.myPlayer) return;` — дублирования только у владельца, что нормально для такого эффекта.
- **SpearReworkPlayer**: использование `LastSpearAttackTick` и `GameUpdateCount` для определения «первого удара после паузы» логично.

## Рекомендуемый порядок исправлений

1. **Обязательно**: добавить текстуры в `Items/` по всем путям выше (или заменить пути на существующие/временные заглушки) и при необходимости переименовать файлы с кириллицы на латиницу.
2. **По задумке**: решить, при попадании копья должен вылетать ванильный серп или модовый — и либо удалить неиспользуемые классы проектий, либо перейти на спавн модовых типов в `OnHitNPC`.
3. **По результату в игре**: при неправильном отражении копья — поправить `PreDraw` (flip/rotation).
4. **По желанию**: выровнять версию в `mod.json` и `build.txt`, переименовать `GlobalItem.cs` в `GlobalSpears.cs`.
